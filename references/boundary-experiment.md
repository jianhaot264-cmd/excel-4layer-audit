# 边界实验：实测四层验证阶梯的**能力边界**

> 一句话结论：**L1 和 L3 共享"读缓存"盲区，L4 只查性质；只有 L2 能回答"引擎重算是否得到这个数"。**
> 这份实验的价值不在"证明工具有效"，而在**测出它在哪里会漏报**。

配套脚本：`scripts/make_traps.py`（自带 demo 样本，可直接跑，只需 openpyxl）。

---

## 一、为什么要做这个实验

四层阶梯听起来层层设防，容易让人以为"过了 L1+L3 就稳了"。但**"看起来严密"和"真的能抓到错"是两件事**。

验证方法只能是：**往一份通过的成品里注入"本该被抓到"的错误，看每一层的实际反应。**
如果某类陷阱能穿过所有层，那这一层对这类错误就是无效的——不管它的文档写得多漂亮。

---

## 二、三类陷阱

| 陷阱 | 注入方式 | 公式 | 缓存 | 该由谁抓 |
|---|---|---|---|---|
| **A 缓存篡改** | `<v>` 改成 `12345` | 正确 | **错** | 只有 L2 |
| **B 公式改错** | 首个区域引用起始行 +1 | **错** | 未同步（旧值） | 只有 L2 |
| **C 越界引用** | 首个区域引用改到第 7000 行外 | **错** | 未同步（旧值） | 只有 L2 |

---

## 三、怎么跑

```bash
# 1. 生成陷阱（不给 --src 就用内置 demo 样本；也可传自己的成品）
python scripts/make_traps.py --out ./边界实验

# 2. 逐份跑 L2（或跑完整四层 run_all.py）
for t in A-缓存陷阱 B-公式错误 C-越界引用; do
    python scripts/recalc_verify.py "./边界实验/$t.xlsx" --engine excel,wps
done
```

## 四、实测结果

### 结论表

| 验证层 | 陷阱 A | 陷阱 B | 陷阱 C |
|---|---|---|---|
| **L1** 独立重实现 | ✖ 漏报 | ✖ 漏报 | ✖ 漏报 |
| **L2** 多引擎重算 | ✔ **命中** | ✔ **命中** | ✔ **命中** |
| **L3** 结构审计 | △ 仅 `--expect` 抓到 1/2 | ✖ 漏报 | ✖ 漏报 |
| **L4** 不变量与边界 | ✖ 漏报 | ✖ 漏报 | ✖ 漏报 |

### 用内置 demo 复现的输出（3 个公式，Excel 引擎）

```
A-缓存陷阱   数据!C1  缓存=12345  引擎=55.0   → ✘ 不一致
B-公式错误   数据!C1  缓存=55     引擎=54.0   → ✘ 不一致
C-越界引用   数据!C1  缓存=55     引擎=0.0    → ✘ 不一致
```

### 当初用真实成品跑（133 个公式）的输出

```
A 缓存篡改   ✘ 48 处不一致（两引擎各自）
B 公式改错   ✘ 24 处不一致（含 LARGE 引用错位导致的连锁错）
C 越界引用   ✘ 48 处不一致（引擎返回 #NUM!，已归一化为错误名）
```

## 五、根因

| 层 | 它实际在"看"什么 | 为什么漏报 |
|---|---|---|
| **L1** | `openpyxl.load_workbook(data_only=True)` → **缓存** | 与写入方同源，缓存错它就跟着错 |
| **L3** | 静态 XML 结构 → **缓存的存在性/格式** | 它只检查"<v> 在不在"，查不出"<v> 对不对" |
| **L4** | 数值之间的**关系**（排名连续、降序、Top-K） | **错的数字同样满足这些性质** |

只有 **L2** 把真实引擎启起来重算（`CalculateFullRebuild`），才真正绕开缓存。

---

## 六、由此固化下来的三条纪律

1. **L2 不可省略。** 它不是"锦上添花的第二意见"，而是唯一能回答
   "引擎重算是不是这个数"的一层。只跑 L1+L3 就宣布"已验证"，
   本质上只是"**我和写入程序对过答案了**"。
2. **L4 全绿 ≠ 数字对了。** 它只证明逻辑自洽——错的数字照样排名连续、照样降序。
3. **交付话术必须与层数匹配。** 走了几层就说几层；"我做了 4 项检查" ≠ "已验证"。

---

## 七、实现这个实验时踩过的两个坑（写脚本时勿重蹈）

1. **只能在 `<f>…</f>` 内部找区域引用。**
   直接对整份 XML 做正则，会先匹配到 `<dimension ref="A1:C3"/>`，
   于是把**维度声明**改了而公式纹丝不动 —— **陷阱静默失效，实验变成空转**。
2. **openpyxl 直出的公式单元格带的是空缓存 `<v></v>`**（不是"没有 `<v>`"）。
   所以 demo 样本必须**显式写入真实的缓存值**，否则"缓存 vs 重算"这一路根本无从比对。

> 附带：越界引用在 `SUM` 这类函数上表现为**数值不符**（空区域 = 0）；
> 若原公式是 `LARGE`/`INDEX`，则会直接报 `#NUM!`/`#REF!`。
> 两者都会被 L2 抓到，属正常。
