# 验证阶梯：怎么把"算对了"变成**可证明**的事

> 一句话结论：**单条路径算出的结果没有自证能力。**
> 「准确率 100%」不是一句声明，而是一组可复现的证据。本文给出这套证据的构造方法。

---

## 一、先说清楚一个认知陷阱：读到的"值"可能不是"真值"

`.xlsx` 里公式单元格长这样：

```xml
<c r="C20" s="23"><f>LARGE($B$7:$B$16,1)</f><v>6256</v></c>
                                    ↑ 公式        ↑ 缓存的**计算结果**
```

`<v>6256</v>` 是**上一个保存这个文件的程序**算出来写进去的。于是：

| 你以为 | 实际 |
|---|---|
| `openpyxl(data_only=True)` 读到的是"计算结果" | 读到的是**缓存**，可能是陈旧的、也可能是别的引擎算错的 |
| "读到 6256，期望 6256，通过" | 只证明了**写入程序**和**期望值**一致，没证明 **Excel** 会算出 6256 |

这不是理论担忧：**任何基于缓存值的"期望值比对"都绕不开它。** 一旦写入方（某个 SDK、某个在线协作端、甚至一个写错的脚本）把缓存写歪了，用户双击打开看到的数字和你验证的数字就是两回事。

**所以：必须至少有一个"重算"动作，且它不能读缓存。**

---

## 二、验证阶梯（L0–L4）

越往下独立性越强、成本越高。**交付声明取决于你走到了哪一级。**

### L0 · 自校验（不算验证）
用同一套工具、同一条路径再算一遍。能挡住手抖，挡不住系统性错误。**不能作为交付依据。**

### L1 · 独立重实现（differential testing）
用自己的代码，**从数据源重新推导**全部答案，再与交付物逐格比对。

- 必须换实现路径：不要复用表格引擎、不要复用同一批公式
- 必须从**数据源**读原始记录，而不是从答案区反读
- 必须**按名称查表**比对（明细是原始顺序、排名是降序，按下标对齐必然假报错）
- 浮点用容差 `abs(a-b) < 0.005`

覆盖面：计算公式写错、引用串行、聚合口径选错。

> ⚠️ **L1 有一个很多人没意识到的硬边界（本次实证）**：L1 读交付物时几乎必然走
> `openpyxl.load_workbook(data_only=True)` —— 而这读的是**缓存**。于是：
> - 若"公式对、缓存被写歪"：L1 读到歪缓存，与它自己算的结果不符 → **能抓到**
> - 若"缓存被写歪、且它与写入方期望一致"：L1 与写入方同源 → **抓不到**
> - 若"公式被改错、缓存仍是旧值"：L1 读到的是旧缓存，与独立重算不符 → **能抓到**
>
> 换言之 **L1 只能证明"缓存值符合从数据源重推的结果"，永远不能证明"引擎重算会得到这个数"**。
> 只有 L2 能穿透这层。**不要把 L1 全绿当成"算对了"。**（实测：三组人为陷阱 L1 全部漏报，L2 全部命中。）

### L2 · 多引擎重算（N-version / 交叉验证）★★ 唯一不可省略的一层
用**其他计算引擎**强制全量重算，四项比对：

1. **缓存值 vs 各引擎重算值** —— 找陈旧/错误的缓存（**L1 和 L3 都发现不了**）
2. **引擎之间逐格交叉比对** —— 暴露引擎实现差异（N-version 的核心价值）
3. **引擎重算值 vs 期望值** —— 权威结论校验
4. **重算后的错误值扫描** —— 重算才会暴露的 `#REF!` / `#VALUE!`

> 🎯 **为什么 L2 不可省略（实证结论）**：在一次受控实验中，往成品里注入三类陷阱
> （① 缓存值篡改 ② 公式引用改错 ③ 越界引用），**L1 全部漏报、L3 只抓到其中 1 个、
> L4 全部漏报；只有 L2 三组全部命中**。
> L2 是整套阶梯里唯一能回答"**引擎重算真的会得到这个数吗**"的一层。
> 没有 L2 的"验证"，本质上只是"我和写入程序对过答案了"。

实现：`scripts/recalc_verify.py`（引擎可插拔，支持同时开多个）。

```bash
python scripts/recalc_verify.py 成品.xlsx --list-engines                        # 探测
python scripts/recalc_verify.py 成品.xlsx --engine excel,wps --expect expected.json --json r2.json
```

#### 引擎注册表

| key | ProgID | 说明 |
|---|---|---|
| `excel` | `Excel.Application` | Microsoft Office |
| `wps` | `KET.Application` | WPS 表格（ET）；文字是 `KWPS.Application` |

#### 探测引擎时的三个坑

1. **WPS 自报名的 `Name` 是 `"Microsoft Excel"`**（兼容层行为）。判定引擎**不能只看 `Name`**，必须 ProgID + 安装路径共同识别——否则会出现"以为在验 Excel、实际跑的是 WPS"的静默错误，白验一场。
2. **ProgID `Excel.Application` 可能被 WPS 接管**（WPS 安装时可选"关联 Office 格式"）。所以脚本会额外校验安装路径，路径不符就发警告。
3. **WPS 常装在非 C 盘**（实测 `E:\WPS Office\12.1.0.28043\office6`）。**不要因为 `C:\Program Files\WPS Office` 不存在就断定没装**——必须用 ProgID 探测。

#### 引擎全不可用时的替代（按可靠性排序）

1. 真 Excel / WPS 引擎（最权威，与接收方二进制一致）
2. `pip install formulas` —— 纯 Python 公式求值库，不需要装 Office
3. LibreOffice headless：`soffice --headless --convert-to xlsx --outdir out in.xlsx`（会重算）
4. 自己写覆盖所用函数子集的小型求值器（可控但要自证，谨慎）

**选择原则**：引擎要"和最终读者不是同一个"就够，**能开两个就开两个**。两个引擎全表逐格一致，可以把"接收方引擎差异"这条残留风险直接划掉——这是单引擎做不到的。

#### 文档类（docx）的同一套阶梯

Word/WPS 文字的盲区与表格**完全同构**：文档里的域结果、表格公式（`=SUM(ABOVE)`）结果，
也是"上一次保存方写进文件的缓存"，不代表重算后的值。

| 表格侧 | 文档侧 |
|---|---|
| 公式缓存 `<v>` | 域（Field）结果 |
| `CalculateFullRebuild()` | `Fields.Update()`（+ 每表 `Tables(i).Range.Fields.Update()`） |
| 单元格值 | 段落文本 / 表格单元格 / 域结果 |
| `Excel.Application` / `KET.Application` | `Word.Application` / `KWPS.Application` |

实现：`scripts/verify_docx.py`。引用写法 `para:N` / `table:T:R:C` / `field:N`。

**有效性判据（照搬 L2 的思路）**：把域缓存**故意写成错值**再跑，看引擎能否算回正确值。
`python scripts/make_docx_field_sample.py` 会生成这样的样本：`=SUM(ABOVE)` 的缓存写成 `999999`，
正确的两引擎都应算回 `60`；若都报 `999999`，说明它们只读了缓存 —— 这次验证白做了。


### L3 · 结构与静态审计
扫那些"不会报错但会致命"的东西：脏 XML、非规范公式标签、缺缓存、版本不兼容函数、引用越界、图表引用错位、原文被覆盖。实现：`scripts/audit_xlsx.py`。

### L4 · 不变量与边界（property-based）
不检查具体数字，而检查**必须成立的性质**：

- 排名是完整的 `1..N`（断号/重号 = 逻辑坏了）
- 降序区真的非递增
- 各分组之和 = 总计（配平）
- **结论区的 Top-K 必须是全量池里的前 K 名** ← 端到端不变量，最值钱
- 无并列卡在第 K 名边界（否则"前三"没有唯一解）
- 结论区没有硬编码数字（绕过了公式）

实现：`scripts/invariant_check.py`。

## 三、什么才算"已验证"（Definition of Done）

只有以下条件**全部**满足，才可以对用户说"已验证"：

- [ ] L1 独立重实现：全部答案逐格吻合，无例外
- [ ] **L2 强制重算（不可省略）**：缓存值 = 重算值（0 处不一致）**且** 重算值 = 期望值（全命中）**且** 重算后 0 错误值
- [ ] L3 结构审计：0 FAIL；每条 WARN 都有解释（修掉或写进交付说明）
- [ ] L4 不变量：0 FAIL；边界 WARN（并列、重复行、类型混杂）都已在交付物中声明
- [ ] 交付说明里写出：口径 / 备选口径 / 数据问题 / 剩余风险

**任一层没跑，就只能说"我做了 X 项检查"，不能说"已验证"。** 这条纪律比任何工具都重要。

> 特别提醒：**只有 L1 + L3 全绿 ≠ 已验证。** 这两层共享同一个盲区（都读缓存），
> 实测中三组注入陷阱它们几乎全部漏报。"没有 L2 的验证"不是验证，是自说自话。

## 四、"准确率 100%"该怎么表述

> **先给结论：本技能不能承诺"绝对 100%"。** 它能做的是把"算得对"变成**可证明**，
> 把"解得对"的歧义**穷尽并显式化**。任何声称"100% 绝对没错"的表述都是未经验证的断言。

诚实的表述分三段：

1. **算得对**（calculation correctness，**可强陈述**）：L1+L2 全绿 →
   > "交付物中每个数字都能溯源到公式；已用独立重实现 + Excel/WPS 双引擎强制重算，逐格一致，0 错误值。"

2. **解得对**（interpretation correctness，**只能说"已穷尽歧义"**）：受题目表述、业务含义约束 →
   > "题目未定义的分母口径存在两种理解，两种结果均已写入工作表并标注差异。"

3. **消不掉的部分**（**必须明说**）：
   > "剩余不确定性：① 口径 A/B 的选择取决于出题人意图 ② 数据源本身的错误无法自证 ③ 若接收方引擎非 Excel/WPS，个别函数行为可能不同。"

**不该说的**：
- ❌ "准确率 100%，绝对没错" —— 未经验证的断言
- ❌ "应该没问题" —— 未验证
- ❌ "L1 和 L3 都过了，肯定对" —— 这两层有共同盲区
- ✅ "已验证：四项检查全绿；剩余不确定性是 X" —— 可核查

专业上的正确姿势是**把不确定性显式化**，而不是消灭它。评审方/阅卷方真正想看到的是：你知道哪些地方可能出错，并且已经把边界情况都摊开了。

### 能力边界的量化（实测）

| 错误类型 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| 公式写错（引用串行/聚合口径选错） | ✔ | ✔ | ✖ | 部分 |
| 缓存值与引擎重算不符 | 部分 | ✔ | ✖ | ✖ |
| 公式引用越界（重算报错） | 部分 | ✔ | ✖ | ✖ |
| 缺缓存 / 脏 XML / 新函数 / 原文被改 | ✖ | ✖ | ✔ | ✖ |
| 排名断号 / 结论区 Top-K 错 / 硬编码 | ✖ | ✖ | ✖ | ✔ |
| **口径理解与出题人意图不符** | ✖ | ✖ | ✖ | ✖ |
| **数据源本身有错** | ✖ | ✖ | ✖ | ✖ |

最后两行**任何工具层都查不出来**——只能靠"把备选口径写进交付物 + 声明数据质量问题"来缓解。
**这就是"100%"无法被承诺的根本原因。**

## 五、残留风险清单（跑完阶梯后仍可能错的）

诚实列出，并在交付说明里对应说明：

| 风险源 | 为什么查不出来 | 缓解 |
|---|---|---|
| **口径理解偏差** | 数学上自洽，但和出题人想要的不一样 | 主口径 + 备选口径都写进表里 |
| **数据源本身是错的** | 只能按给定数据算 | 数据质量说明（重复行、异常值、类型混杂） |
| **接收方引擎差异** | 不同 Office/WPS 版本对个别函数处理不同 | **开两个引擎全表交叉比对**（本机有 Office + WPS 时可直接消除）；只用版本安全函数 |
| **题面之外的隐含前提** | 无从得知 | 显式声明假设 |
| **日期/时区/序列号** | 1900/1904 日期系统差异 | 确认日期系统；避免跨系统比较 |

## 六、可复现证据（Reproducibility Artifact）

交付时除了文件，附上可复现的证据包，让任何人都能重跑：

```bash
# 一条命令跑完全部四层，产出证据包（report.md / report.json / 各层原始输出）
python scripts/run_all.py 成品.xlsx \
       --orig 原始.xlsx --expect expected.json --invariants invariants.json \
       --source 数据源表 --l1 我的独立重算.py --out ./验证报告
```

`--l1` 挂的是**任务专属**的独立重实现脚本（L2/L3/L4 是通用的，L1 不可能通用）。
不挂 L1 时报告会明确标注"未执行"，不会假装通过。

底层等价于分别跑：

```bash
python scripts/recalc_verify.py   成品.xlsx --engine excel,wps --expect expected.json --json r2.json
python scripts/audit_xlsx.py      成品.xlsx --orig 原始.xlsx --expect expected.json    --json r3.json
python scripts/invariant_check.py 成品.xlsx --spec invariants.json --auto-edge          --json r4.json
```

报告里记下文件校验值，保证"验证的就是交付的那个文件"：

```bash
sha256sum 成品.xlsx        # Linux / Git Bash
certutil -hashfile 成品.xlsx SHA256   # Windows CMD
```

**引擎验证后要重算一次哈希**：COM 打开如有任何写回，文件就变了，此前结论全部失效（见 `pitfalls.md` P14）。

**顺序纪律**：任何一次修改之后，**必须重跑全部四层**。改一个单元格就等于之前的结论全部失效——这是最容易破功的地方。
