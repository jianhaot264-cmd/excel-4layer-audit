# JT Excel 数据统计分析 · 四层审计

> 把「表格数据统计分析」做成**可被第三方复核的交付**，而不是一次性的填数。

Excel / WPS 表格任务最大的风险不是"算不出来"，而是**算错了却看不出来**。

---

## 它解决的那个致命盲区

`.xlsx` 里公式单元格存的 `<v>` 字段，是**上一次保存方写入的缓存**，不是"真值"。

```
<c r="C20"><f>LARGE($B$7:$B$16,1)</f><v>6256</v></c>
                                  ↑ 公式    ↑ 上次存文件的人算出来写进去的数
```

于是「读出来 → 跟期望值比 → 通过」这条最自然的验证路径，
只证明了**写入程序和期望值一致**，完全没证明 **Excel 会算出这个数**。

任何基于缓存值的"期望值比对"都绕不开这个洞。**这个技能的四层验证阶梯，就是为了把它堵上。**

---

## 四层验证阶梯

| 层 | 做什么 | 关键限制 |
|---|---|---|
| **L1** 独立重实现 | 从数据源用纯代码重推全部答案，逐格比对 | 读的是缓存，与写入方同源 |
| **L2** 多引擎强制重算 ★ | Excel + WPS 各自 `CalculateFullRebuild`，四项交叉比对 | **唯一不可省略的一层** |
| **L3** 结构审计 | 14 项静态检查（脏 XML / 前导等号 / 新函数 / 越界 / 原文被改…） | 只查缓存"在不在"，不查"对不对" |
| **L4** 不变量与边界 | 排名连续 / 降序 / 配平 / 结论区 Top-K = 全量池前 K 名 | 只证明逻辑自洽，不证明数字正确 |

### 为什么 L2 不可省略（这是实测结论，不是推理）

往一份已通过的成品注入三类"本该被抓到"的陷阱，看每层的实际反应：

| 陷阱 | L1 | **L2** | L3 | L4 |
|---|---|---|---|---|
| 缓存篡改（公式对、缓存错） | 漏报 | **命中** | 仅带期望清单时抓到 1/2 | 漏报 |
| 公式改错（引用少一行） | 漏报 | **命中** | 漏报 | 漏报 |
| 越界引用（重算必报错） | 漏报 | **命中** | 漏报 | 漏报 |

**根因**：L1 走 `openpyxl(data_only=True)`、L3 走静态 XML，**两者读的都是缓存**；
L4 只查性质，而**错的数字同样满足"排名连续、降序、Top-K 一致"**。

⇒ 「L1 + L3 全绿 ≈ 已验证」是错的，那只是"**我和写入程序对过答案了**"。
⇒ **L2 是整套方法里唯一能回答"引擎重算是不是这个数"的一层。**

复现这个实验：`python scripts/make_traps.py --out ./边界实验`

## 能力边界（先说清楚，避免误导）

**✅ 可以强陈述**
> "交付物中每个数字都能溯源到公式；已用独立重实现 + Excel/WPS 双引擎强制重算，
> 逐格 0 差异、0 错误值；验证前后文件哈希一致。"

**❌ 不能承诺"准确率 100%"** —— 有两类错误**任何工具层都查不出来**：

1. **口径理解与出题人意图不符** → 数学上自洽，但答非所问
2. **数据源本身有错** → 只能按给定数据算

缓解手段：主口径 + 备选口径**都写进交付物**；数据质量问题**显式声明**。

> 正确话术：「已验证：四层全绿；**剩余不确定性是 X**」
> 错误话术：「准确率 100%，绝对没错」

## 覆盖的统计场景

分组汇总与排名 · 口径统计（求和 / 计数 / 去重 / 日均）· 同比环比与占比 ·
数据清洗与质量体检 · 条件筛选与 Top-K · 透视与图表 · 公式建模 · 做题作答 · 报表生成

同一套阶梯也适用于 **docx**（Word / WPS 文字）：域结果与表格公式同样是缓存，
用 `Fields.Update()` 重算后再比对。

---

## 附带的可执行脚本

| 脚本 | 用途 |
|---|---|
| `run_all.py` | 一键跑完四层并产出证据包（`report.md` + `report.json` + 各层原始输出） |
| `selftest.py` | 工具链自检（45 项 / 带引擎 47 项）——**换机器后先跑它** |
| `recalc_verify.py` | ★ L2 多引擎强制重算（Excel + WPS 交叉比对） |
| `audit_xlsx.py` | L3 结构审计（14 项静态检查） |
| `invariant_check.py` | L4 不变量与边界（7 类 spec + 数据源自动体检） |
| `make_traps.py` | 边界实验：注入三类陷阱，实测各层能否捕获 |
| `patch_cells.py` | 直接改 XML 写单元格（不经过引擎，不抢文件锁，写入后自校验失败自动回滚） |
| `fix_formula_tags.py` | 归一化公式标签（去前导等号 + 消除数组标记） |
| `verify_docx.py` | docx 孪生：Word + WPS 文字各自 `Fields.Update()` 重算后比对 |

---

## 三条使用纪律

1. **口径先定，且落进表里。** 歧义项要把主口径与备选口径**都**写出来。
2. **不准读缓存值当结论。** 至少用**另一个引擎强制重算**一遍。
3. **任何修改后重跑全部四层。** 改一个单元格 = 之前的结论全部失效。

---

## 快速开始

```bash
# 0) 换机器后先自检，证明工具链是好的（不触碰任何真实文件）
python scripts/selftest.py

# 1) 一条命令跑完四层并产出证据包
python scripts/run_all.py 成品.xlsx \
       --orig 原始文件.xlsx --expect expected.json --invariants invariants.json \
       --source 数据源表 --l1 任务专属重算.py --engines excel,wps --out ./验证报告
```

退出码：`0` 全过 ｜ `1` 有 FAIL ｜ `3` 有层未执行（部分验证）｜ `2` 前置不满足。

> `--l1` 挂的是**任务专属**的独立重实现脚本（L2/L3/L4 通用，L1 不可能通用）。
> 不挂 L1 时报告会明确标注"未执行"，**不会假装通过**。
