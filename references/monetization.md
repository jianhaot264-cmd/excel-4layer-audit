# 变现设计：从免费 Skill 到付费服务

> 这份文档回答一个问题：**技能上架之后，钱从哪来。**
> 先说结论，再给框架，最后给冷启动路径。

---

## 零、先管理预期：上架 ≠ 变现

SkillHub 首页的"月收益 ¥3.19 万"是**示例数据**，不是个人水平。真实机制是：

| 层 | 平台提供什么 | 你要提供什么 | 收入来源 |
|---|---|---|---|
| **免费层** | 分发、搜索、下载、评测反馈闭环 | 优质 Skill + 清晰 README + 关键词 | **无直接收入**，换来安装量与口碑 |
| **付费层（SkillPay）** | 按次计费、结算、支付宝绑定 | **一个真实可交付的付费服务** | 调用量 × 单价 |

⚠️ **关键限制（实测）**：
- **CLI 只能发布「技能包」，不能发布「收费」**。定价、Pay Skill 计费、支付宝 serviceId 绑定**只能在网页端做**。
- 平台会抽成（具体比例以网页端实际显示为准）。
- 审核三线并行：内容合规 + 科恩实验室漏洞扫描 + 云鼎实验室 AI 模型安全评估，任一不过即拒。

**所以路径是：先有真实服务能力 → 再把服务挂到 SkillPay → 技能免费当流量入口。**
反过来（先上架技能、坐等收入）几乎不可能有结果。

## 一、你的第一个付费客户，就在审计 / 内控交付现场

这是本方案最重要的一条，优先于任何"产品化"思考。

以审计 / 内控交付现场为例（内控问题检查、穿行测试、底稿填制），
典型工作包括：经责审计抽样复核、研发费用与工时归集核查、
穿行测试底稿、费用与采购内控检查（车辆、周转房、零星采购）。

**这些工作的共同点，和本技能的适用场景完全重合：**

| 审计/内控工作 | 本技能对应能力 |
|---|---|
| 抽样复核、底稿数据与原始凭证勾稽 | L1 独立重实现（从数据源重推，与底稿逐格比对） |
| 多表数据汇总、供应商/往来款分析 | L2 多引擎重算 + L4 不变量（配平、排名连续） |
| 底稿 Excel 交付后怕算错、口径说不清 | L3 结构审计 + 口径卡 + 备选口径显式化 |
| 审计结论要"经得起复核" | 全套产出物 = 可复现证据包（report.md + 四层原始输出 + SHA256） |

**这意味着你手上就有一个真实的、可收费的交付物：**
> 「Excel 底稿交付前的四层自动复核」——AI 跑完四层，人签字，交付审计底稿。

**这不是副业，是你把交付现场的能力标准化。** 而且它天然解决冷启动：
第一个用户就是你的项目组/师父，他们本来就在天天干这件事。

**⚠️ 合规红线（必须先确认）**
- 你的项目协议大概率含**保密条款与成果归属**条款。把工作方法沉淀成通用方法论通常没问题，
  但**绝不能把客户的真实数据、底稿、客户名带进任何公开的 skill / 评测 / README**。
- 本技能的边界实验用的是**合成的自造样本**（`make_traps.py` 自带 demo），不含任何真实客户数据——
  这点必须保持，不要为了"举例真实"而越线。
- 是否可以将方法论对外发布，**以你的劳动合同/项目协议为准**，不确定就问 HR。

## 二、定价框架（成本锚 + 价值锚，取高者）

### 2.1 成本锚（保本线）

一次完整四层验证的人工投入：写 L1 独立重实现脚本 0.5–1.5h，其余自动化 0.2h。
按 ¥150/h 计：

| 档位 | 人工 | 保本价 | 建议零售价 |
|---|---|---|---|
| 轻（单表、<1000 行、口径明确） | ~0.5h | ¥75 | **¥299–599** |
| 中（多表、需交叉验证、口径需澄清） | ~1.5h | ¥225 | **¥999–1999** |
| 重（多源数据 + 清洗 + 口径重构） | ~3h | ¥450 | **¥2999–5999** |

> ⚠️ **真实成本远不止工时**：一次漏检造成的返工、一次错误结论引发的信任崩塌，
> 都是成本。保本价只是地板，零售价必须覆盖**风险溢价**。

### 2.2 价值锚（天花板）

| 场景 | 一次错误统计口径导致的代价 | 定价可到 |
|---|---|---|
| 个人/小团队报表 | 几百到几千（返工） | ¥599–1999 |
| 审计/内控底稿 | 报告需重做、项目延期 | ¥2999–9999 |
| 投决/授信/并购模型 | 一次错判 = 数万到数十万 | ¥9999+ 或按项目 |

**取两者高者。** 审计场景的价值锚很高，这是本方案定价上探的底气。

### 2.3 三层产品形态

| 层 | 形态 | 定价 | 交付物 | 自动化程度 |
|---|---|---|---|---|
| **Free** | Skill 本身 | ¥0 | 方法论 + 可执行脚本 | 100%（用户自己跑） |
| **Pro** | 单次底稿复核 | ¥999–5999/次 | 四层报告 + 人工签字复核 + 口径说明 + 剩余风险清单 | 80%（AI 跑 + 人签字） |
| **Team** | 月度包 + 口径库 | ¥1999–9999/月 | 持续复核 + 团队口径知识库 + 优先响应 | 70% |
| **Enterprise** | 私有部署 + 定制 | ¥3万–20万/年 | 内部 Skill 化 + 口径库定制 + SLA | 50% |

> 关键洞察：**Pro 层的「人工签字」不是成本中心，是定价锚。**
> 审计/财务场景里，交付物要有人承担责任——这正是付费方买的东西。

## 三、付费层交付物清单（要能真交付，才敢挂 SkillPay）

一次 **Pro 单次复核**的标准交付物（建议直接固化成模板）：

1. `复核报告.md` — 结论 + 四层结果 + 每条 WARN 的解释
2. `四层原始输出/` — L1/L2/L3/L4 的 JSON + 文本输出（可复核）
3. `口径卡.md` — 主口径 + 备选口径 + 差异影响 + 名次影响
4. `数据质量清单.md` — 重复行、类型混杂、异常值、零值、单成员分组
5. `剩余风险.md` — 明确列出哪些无法由计算消除
6. `SHA256.txt` — 证明"复核的就是交付的那个文件"

> 这 6 项**就是本技能四层验证的天然产物**。这不是重新造轮子，
> 而是**把 skill 的输出直接变成收费交付物**——这是本方案最省力的地方。

## 四、SkillPay 接法（按官方发布器实测信息）

### 4.1 边界（务必分清）

```
CLI  能做：发布技能包（slug/displayName/version/summary/license + 文件）
CLI  不能：定价、Pay Skill 计费、支付宝 serviceId 绑定
     → 这些只能在网页端 skillhub.cn/dashboard 做
```

### 4.2 步骤

1. **网页端**发布/更新技能（CLI 推包 → 网页端配价 → 审核通过）
2. **网页端**配置 Pay Skill：定价、计费方式、支付宝 serviceId 绑定
3. 用户在你的技能详情页触发付费调用 → 平台按次计费 → 你的服务履约 → 平台结算

### 4.3 一个必须先想清楚的问题

**SkillPay 是"按调用计费"，但你的服务是"按次交付"。**
这中间的差额谁承担？

- 方案 A：**纯调用**——skill 直接对接你的后端 API，用户一次调用即完成一次复核。
  要求：你的复核能力必须**完全自动化**（那 L1 独立重实现脚本就得能对任意上传表格自动生成）。
  ⚠️ 当前 L1 是任务专属的，这是最大的技术缺口。
- 方案 B：**调用 + 人工履约**——skill 负责跑四层并产出证据包，人工只做复核与签字。
  按次计费，但履约不实时。计费语义要向用户讲清楚。
- 方案 C：**先不挂 SkillPay**，用 skill 免费拉量，付费走企业区区的直接签约（线下结算）。
  **起步阶段推荐这个**——先把"有人愿意付钱"验证了，再考虑平台结算。

## 五、冷启动路径（前 10 个付费用户）

| 阶段 | 动作 | 目标 |
|---|---|---|
| **0–1 周** | 技能上架 SkillHub（免费层），观察下载/评分 | 让市场知道有这个能力 |
| **1–2 周** | 在交付现场把"底稿四层复核"跑 3 次真实案例，**不收钱**，只收反馈 | 验证交付物清单够不够、耗时多久 |
| **2–4 周** | 找 1 个朋友/同学/前同事收 ¥999 首单（可给大幅优惠换案例授权） | 验证付费意愿与交付边界 |
| **4–8 周** | 沉淀 3–5 个可复用口径卡模板（按行业/场景） | 让交付边际成本下降 |
| **8–12 周** | 谈第一个团队客户（月度包） | 收入从"次"变"月"，可预测 |

**冷启动的关键指标**：
- 技能：下载量、评测分（SkillHub 有 `skill evaluation <slug> --json` 可取）
- 业务：单次实际耗时（决定能接多少单）、首次通过率、复购率

## 六、竞争与差异化

| 竞品类型 | 他们的强项 | 你的差异化 |
|---|---|---|
| 通用 Excel 助手类 Skill | 覆盖面广、量大 | **"验证"而非"帮你算"**——四层证据包 + 可复现 |
| 单纯的公式/函数类 Skill | 即用即用、门槛低 | 你解决的是"交付前的正确性"，场景更窄更深 |
| 人工审计/复核服务 | 权威、可担责 | AI 跑 + 人签字 = 成本降一个量级，覆盖长尾小单 |
| 通用代码执行类 Skill | 灵活 | 领域口径知识（统计/审计/财务）+ 明确的不变量库 |

**你的护城河不是脚本，是「口径知识 + 不变量库 + 证据包格式」**。
脚本谁都能写；**"这类表该查什么、该声明什么"是经验**。

## 附：一条重要提醒

**SkillHub 的免费层不是收入，是获客成本。**
你现在投入的上架精力（发布、README、评测反馈迭代）属于**市场费用**，
不是"做产品"。所以要清楚：**免费层的 KPI 是安装量和评分，付费层的 KPI 是复购率。**
两层的衡量方式完全不同，混在一起看会做出错误决策。
